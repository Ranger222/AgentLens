# AgentLens v1 — Design Brief

**Status:** Authoritative build spec. Resolves the four research findings into concrete, opinionated decisions an engineer can implement directly.
**Date:** 2026-06-25
**Audience:** Implementing engineer(s).

This brief assumes the existing scaffolding under `src/agentlens/` (models, context, ids, config, serialization, storage) and *amends* it where research conflicts with what was scaffolded. Every amendment is called out explicitly under **"AMEND"**. Where the scaffolding already made the right call, this brief ratifies it so nobody re-litigates it.

---

## 0. Guiding principles (non-negotiable)

1. **Frictionless DX.** `@trace`, `with span(...)`, and one-call `instrument_openai()` must be all a user needs. Parent/child is *always* inferred from `contextvars` — users never pass parent IDs.
2. **Never crash the user's app.** Every tracing side effect (serialize, contextvar set/reset, DB write) is wrapped so a tracing bug degrades to "missing span," never a raised exception in user code.
3. **Never block the hot path.** Completed spans are enqueued to a background writer thread. No tokenization, no cost math, no large-object serialization on the caller's thread beyond a cheap capture.
4. **stdlib-only SDK core.** `import agentlens` pulls in only the standard library (`contextvars`, `inspect`, `functools`, `traceback`, `json`, `sqlite3`, `threading`, `queue`, `dataclasses`, `os`, `secrets`, `time`). `fastapi`/`uvicorn` live behind a `[server]` extra and are imported lazily. `openai`/`anthropic` are imported only inside their integration modules. `wrapt` is an *optional accelerator* with a stdlib fallback — not a core dep.
5. **Local-first wedge.** `pip install`, one SQLite file, `agentlens demo` (no keys), `agentlens serve`. No accounts, no Docker, no extra services. Protect this ruthlessly; resist feature creep (no evals/datasets/prompt-mgmt/cost-dashboards in v1).
6. **Loosely OTel/OpenInference-compatible, zero OTel dependency.** Use OTel/OpenInference *names* and id formats so a future `agentlens export --otlp` is trivial, but never import `opentelemetry-*` into the core.

## 2. Span / Run data model

A **two-table** model: `runs` (one row per traced execution ≈ an OTel trace) and `spans` (one row per operation, self-referencing via `parent_id` ≈ OTel span). This mirrors OTel/OpenInference/Langfuse and validates the scaffolded design.

### 2.1 Identifiers — RATIFY existing, with one tweak

Existing `ids.py` uses `os.urandom(16).hex()` (run, 32 hex) and `os.urandom(8).hex()` (span, 16 hex). This matches OTel's `trace_id` (16 bytes) and `span_id` (8 bytes) formats — **keep it.**

- **AMEND:** switch `os.urandom` → `secrets.token_hex(16)` / `secrets.token_hex(8)`. Functionally identical bytes, but `secrets` documents CSPRNG intent and is the research-recommended call. Guard against the all-zero id (invalid per OTel) — astronomically unlikely with a CSPRNG, but assert-non-zero in a unit test.
- `run_id` **is** the OTel `trace_id`. Carry `run_id` on **every** span (denormalized) so "load whole run tree" is one indexed query, never a recursive CTE. (Langfuse's perf rewrite did exactly this.)
- `parent_id` = parent's `span_id`, or `NULL` for the run-root span.

### 2.2 Span type enum — RATIFY existing set, treat as open string

`SpanType` (subclass of `str`) currently defines: `llm_call`, `tool_call`, `agent_step`, `chain`, `retrieval`, `custom`. **Keep this.** It is a superset of the brief's required three and gives headroom. Store as a **TEXT column, never a hard DB enum**, and **never reject** an unknown user-supplied string.

- `agent_step` is the **default and catch-all** (≈ OpenInference `AGENT`/`CHAIN`).
- Document the mapping to OpenInference `openinference.span.kind` and OTel `gen_ai.operation.name` (table below) — used *only* by a future OTLP exporter, not at runtime.

| AgentLens `type` | OpenInference kind | OTel `gen_ai.operation.name` |
|---|---|---|
| `llm_call` | `LLM` | `chat` / `text_completion` |
| `tool_call` | `TOOL` | `execute_tool` |
| `agent_step` | `AGENT` / `CHAIN` | `invoke_agent` / `invoke_workflow` |
| `chain` | `CHAIN` | `invoke_workflow` |
| `retrieval` | `RETRIEVER` | `retrieval` |
| `custom` | (free string) | (free string) |

### 2.3 Status enum — AMEND existing

Existing `SpanStatus`: `running`, `ok`, `error`. Research recommends OTel's `unset`/`ok`/`error`.

**Decision: keep `running` for live/in-flight spans (genuinely useful for a local dashboard that may render an in-progress run); `unset` is NOT needed.** Final resolved set:

```python
class SpanStatus(str):
    RUNNING = "running"   # span started, not yet ended (default at creation)
    OK = "ok"             # ended without exception
    ERROR = "error"       # ended via a raised exception
```

Rationale: OTel's `UNSET` exists because OTel spans can end without a deliberate status; AgentLens *always* resolves to `ok` or `error` on span end, so `unset` would never persist. `running` carries strictly more information than `unset` for the live-render case. The exporter maps `running`→`UNSET`, `ok`→`OK`, `error`→`ERROR` at export time. **Document this as a deliberate divergence from OTel.**

- Run status rolls up from its spans: **`error` if any span errored, else `ok` once the root ends, else `running`.**

### 2.4 Timestamps — AMEND to integer nanoseconds (with derived ms)

This is the most important model amendment. Existing `Span` stores `start_time`/`end_time` as **float epoch seconds** and derives `duration_ms`. Research is emphatic: nested agent spans are frequently sub-millisecond, and float-second math loses ordering/precision; OTel stores ns.

**Decision: store integer nanoseconds; derive `duration_ms` as REAL for the UI.**

- `start_time_ns: int` (`time.time_ns()` at span start — wall clock, for absolute positioning on the timeline).
- For **duration**, capture `time.perf_counter_ns()` at start and end and compute `duration_ns = perf_end - perf_start` (monotonic — immune to clock shifts, retries, NTP steps). Set `end_time_ns = start_time_ns + duration_ns`. This preserves the *good* idea already in the scaffolding (monotonic duration + wall-clock anchor) while upgrading the unit to ns.
- Persist `duration_ms: REAL = duration_ns / 1e6` so the dashboard renders bars without recompute.
- **Keep `seq`** (per-run monotonic insertion order) as the stable tiebreaker for sibling spans that share a `start_time_ns`. This is a genuinely good idea already in the scaffolding and makes the LangSmith "single sortable key" trick unnecessary — `ORDER BY start_time_ns ASC, seq ASC` gives correct chronological order with one index. **Ratify `seq`.**
- **Unit discipline:** ns stored everywhere, ms for display only. Document loudly. The frontend divides ns consistently (see §6).

### 2.5 Token usage — RATIFY existing (OTel-aligned)

Existing `TokenUsage{input_tokens, output_tokens, total_tokens}` with `total` derived in `__post_init__`. **Keep verbatim** — this is exactly the research recommendation (OTel `gen_ai.usage.input_tokens`/`output_tokens` naming, derive total). Normalize *at instrumentation time* from each vendor's shape:

| Source | input | output |
|---|---|---|
| OpenAI raw | `usage.prompt_tokens` | `usage.completion_tokens` |
| Anthropic raw | `usage.input_tokens` | `usage.output_tokens` |
| **AgentLens internal** | `input_tokens` | `output_tokens` |

Persist a flattened `total_tokens INTEGER` column on `spans` (already done) so the runs-list `SUM()` rollup is cheap.

### 2.6 Error info — RATIFY existing

`ErrorInfo{type, message, traceback}` with `from_exception`. **Keep.** `type` == exception class name (== OTel `error.type`). Capture the formatted traceback *inside* the `except` block (before it exits, while `e.__traceback__` is live): `"".join(traceback.format_exception(type(e), e, e.__traceback__))`. Store as its own column so the dashboard shows class + stack separately from a one-line status message.

### 2.7 Field reference (final `Span`)

| Field | Type | Notes |
|---|---|---|
| `span_id` | `str` (16 hex) | PK |
| `run_id` | `str` (32 hex) | = trace_id, denormalized on every span |
| `parent_id` | `str \| None` | NULL = run root |
| `name` | `str` | from `@trace` → `func.__qualname__`; from `span()` → required arg; from auto-instr → `"{op} {model}"` e.g. `"chat gpt-4o"` |
| `type` | `str` | one of §2.2, open |
| `status` | `str` | §2.3 |
| `start_time_ns` | `int` | `time.time_ns()` |
| `end_time_ns` | `int \| None` | `start + duration_ns`; None while running |
| `duration_ms` | `float \| None` (property) | derived |
| `input` | `Any` | safe-serialized at capture |
| `output` | `Any` | safe-serialized at capture |
| `error` | `ErrorInfo \| None` | |
| `usage` | `TokenUsage \| None` | |
| `model` | `str \| None` | convenience mirror of `attributes["gen_ai.request.model"]` |
| `attributes` | `dict[str, Any]` | **NEW (see §2.8)** |
| `metadata` | `dict[str, Any]` | user free-form (kept distinct from `attributes`) |
| `seq` | `int` | per-run insertion order tiebreaker |

### 2.8 `attributes` bag — AMEND (add the OTel seam)

**Add an `attributes: dict[str, Any]` field to `Span` and `Run`**, persisted as a JSON TEXT column. This is the seam that buys OTel/OpenInference interop at zero runtime cost. Auto-instrumentation populates it with **canonical dotted keys**:

```
gen_ai.provider.name      # "openai" | "anthropic"
gen_ai.request.model      # "gpt-4o" | "claude-3-5-sonnet-..."
gen_ai.request.temperature, gen_ai.request.max_tokens, gen_ai.request.top_p
gen_ai.response.id, gen_ai.response.finish_reasons
gen_ai.tool.name          # tool spans
session.id, user.id, tag.tags   # optional, user-set
```

Keep `model` as a first-class column (it's the one attribute the UI shows on every LLM row) **and** mirror it into `attributes["gen_ai.request.model"]`. Everything else lives in `attributes`. **Do NOT** normalize attributes into an EAV key/value table — one JSON column per row (the Phoenix/Langfuse approach) is faster and simpler for local-first scale.

> Keep `metadata` (user-supplied, arbitrary) separate from `attributes` (canonical instrumentation keys). Users set `metadata` via `span(..., metadata={...})`; the SDK sets `attributes`.

## 3. Storage schema (SQLite)

### 3.1 DDL (amended from scaffolding)

```sql
PRAGMA journal_mode = WAL;        -- concurrent reader (dashboard) + writer (SDK)
PRAGMA synchronous = NORMAL;      -- fast, safe-enough for a local dev tool
PRAGMA foreign_keys = ON;
PRAGMA user_version = 1;          -- schema version; bump + migrate on change

CREATE TABLE IF NOT EXISTS runs (
    run_id     TEXT PRIMARY KEY,           -- = trace_id (32 hex)
    name       TEXT,
    status     TEXT NOT NULL,              -- running|ok|error
    start_time_ns INTEGER NOT NULL,
    end_time_ns   INTEGER,
    duration_ms   REAL,                    -- derived, persisted for cheap list render
    attributes TEXT,                       -- JSON
    metadata   TEXT,                       -- JSON
    created_at INTEGER NOT NULL            -- time_ns() at insert
);

CREATE TABLE IF NOT EXISTS spans (
    span_id       TEXT PRIMARY KEY,        -- 16 hex
    run_id        TEXT NOT NULL,           -- = trace_id, denormalized
    parent_id     TEXT,                    -- self-ref; NULL = root
    name          TEXT NOT NULL,
    type          TEXT NOT NULL,
    status        TEXT NOT NULL,
    start_time_ns INTEGER NOT NULL,
    end_time_ns   INTEGER,
    duration_ms   REAL,
    input         TEXT,                    -- JSON string (lazy-parsed)
    output        TEXT,                    -- JSON string (lazy-parsed)
    error         TEXT,                    -- JSON {type,message,traceback}
    usage         TEXT,                    -- JSON {input_tokens,output_tokens,total_tokens}
    total_tokens  INTEGER,                 -- flattened for SUM() rollups
    model         TEXT,
    attributes    TEXT,                    -- JSON
    metadata      TEXT,                    -- JSON
    seq           INTEGER NOT NULL,        -- per-run insertion order
    FOREIGN KEY (run_id) REFERENCES runs(run_id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_spans_run        ON spans(run_id);
CREATE INDEX IF NOT EXISTS idx_spans_parent     ON spans(parent_id);
CREATE INDEX IF NOT EXISTS idx_spans_run_order  ON spans(run_id, start_time_ns, seq);
CREATE INDEX IF NOT EXISTS idx_runs_start       ON runs(start_time_ns DESC);
```

**Changes from scaffolding:** `start_time/end_time REAL` → `*_ns INTEGER` + persisted `duration_ms REAL`; add `attributes` columns; add the composite `(run_id, start_time_ns, seq)` index for one-pass ordered tree builds; add a real `FOREIGN KEY ... ON DELETE CASCADE` (and keep the manual cascade in `delete_run` as belt-and-suspenders since `PRAGMA foreign_keys` is per-connection).

### 3.2 Background writer — AMEND (the #1 architecture change)

The scaffolded `SQLiteStorage` writes **synchronously on the caller's thread** under a lock (and even does a `SELECT COUNT(*)` per `save_span` to compute `seq`). Research is unambiguous that synchronous, on-hot-path writes are the Langfuse "50s → 10ms" disaster. **Introduce a background writer.**

Design:
- A module-level `SpanWriter` owns a `queue.Queue` and a single daemon thread. The thread holds the *only* write connection (so SQLite sees one writer; WAL lets the dashboard process read concurrently).
- SDK code does: build `Span`, **enqueue** it, return. The enqueue is the only thing on the hot path. Serialization of `input`/`output` happens at *capture time* (cheap, bounded, see §4.6) so the queued object is already JSON-ready; the heavy `json.dumps`+truncate runs on the writer thread.
- The writer **batches**: drain up to N items (e.g. 128) or a short timeout (e.g. 50 ms), then one transaction (`BEGIN; INSERT...; COMMIT;`). Batching turns many tiny commits into few.
- Compute `seq` **in the writer**, per-run, from an in-memory `dict[run_id -> counter]` — **no `SELECT COUNT(*)` per span** (that current pattern is O(n²) over a run and a hidden hot-path read). Fall back to a max(seq)+1 query only on cold start for a pre-existing run.
- **`flush()`** (block until queue drained) and an **`atexit`** hook that flushes + closes. The CLI `demo` and tests call `flush()` explicitly so data is on disk before the dashboard reads it.
- The writer thread is **fail-silent**: a write error logs at WARNING and drops that batch; it never propagates and never kills the thread (catch, log, continue).
- Spans are written **once, on completion** (status already `ok`/`error`). v1 does **not** stream partial/in-flight spans to the DB — simpler, and the dashboard is for post-hoc inspection. (`running` status exists for the in-memory/live case and for crash-truncated runs.)

Keep the `Storage` ABC and `SQLiteStorage` read methods (`list_runs`, `get_run`, `get_spans`, `count_runs`, `delete_run`) **as-is** (they're well-formed). The dashboard opens its **own read-only connection** (`mode=ro`, WAL) to the same file. Read endpoints must **not** `json.loads` every span's `input`/`output` — return them as raw strings in list/tree projections and parse only on single-span detail (the Langfuse v1→v2 lesson).

### 3.3 DB path resolution — AMEND precedence

Existing `resolve_db_path`: `arg → $AGENTLENS_DB → ./agentlens.db`. Research wants a home-dir fallback so the dashboard always finds the SDK's DB. **Final precedence (identical for SDK and CLI):**

```
explicit init(db_path=)/--db  >  $AGENTLENS_DB  >  ./agentlens.db (if CWD writable)  >  ~/.agentlens/agentlens.db
```

**Print the resolved absolute path** on (a) first SDK write and (b) `serve` startup. The #1 "it says no runs" footgun is the SDK writing `./agentlens.db` while `serve` reads `~/.agentlens/...`. One shared resolver + a printed path eliminates it.

## 4. Python SDK API shape

`import agentlens` exposes ~7 names and stays stdlib-only:

```python
from agentlens import (
    trace,                 # decorator
    span,                  # context manager / manual handle
    init,                  # configure (db path, run name, enable/disable, caps)
    current_span,          # -> Span | None
    current_run,           # -> Run | None
    instrument_openai,     # explicit wrapper (LangSmith-style)
    instrument_anthropic,
)
from agentlens import Span, SpanType, SpanStatus, Run  # types for annotations
```

`agentlens/__init__.py` uses **PEP 562 `__getattr__`** so `serve`/`create_app` (which import FastAPI) resolve lazily and never load on a plain `import agentlens`.

### 4.1 `init()` / configuration

```python
def init(
    *,
    db_path: str | None = None,
    run_name: str | None = None,
    enabled: bool = True,
    capture_io: bool = True,
    capture_content: bool = True,    # capture LLM message bodies (default on for local DX)
    max_value_bytes: int = 64 * 1024,
    redact_keys: tuple[str, ...] = ("api_key", "authorization", "api-key", "token", "secret"),
) -> None: ...
```

Ratifies the scaffolded `Config` (`enabled`, `capture_io`, `max_value_len`) and adds `capture_content`, `run_name`, and `redact_keys`. Env overrides keep the scaffolded names (`AGENTLENS_DB`, `AGENTLENS_DISABLED`, `AGENTLENS_CAPTURE_IO`, `AGENTLENS_MAX_VALUE_LEN`). `enabled=False` makes `@trace`/`span()` near no-ops (user code still runs) — keep this for prod/tests.

### 4.2 Run lifecycle (implicit)

There is **no explicit "start run" in the common path.** On the **first** span created when no run is active, the SDK **auto-creates a `Run`** (id, `run_name` or a default, `start_time_ns`), pushes it onto `_current_run`, and that span becomes the root. The run ends when its root span ends. Provide an optional explicit `with agentlens.run(name="..."):` context for users who want to group several top-level spans into one run — but it is **not required**.

### 4.3 `@trace` — dispatch on all four function shapes

```python
def trace(
    func=None, *, name: str | None = None, type: str = SpanType.AGENT_STEP,
    capture_input: bool = True, capture_output: bool = True,
): ...
```

- Usable bare (`@trace`) and parameterized (`@trace(type="tool_call")`) — detect "first positional arg is callable."
- **Branch via `inspect`, order matters:** `isasyncgenfunction` → async-gen wrapper; **then** `iscoroutinefunction` → async wrapper; **then** `isgeneratorfunction` → sync-gen wrapper; **else** sync wrapper. (Checking coroutine before async-gen misclassifies async generators — explicit pitfall.)
- Each wrapper: best-effort serialize input → start span → run body in `try/except/finally` → on exception record `ErrorInfo` + `status=error` and **re-raise** → in `finally` capture output, set end time, enqueue span.
- **Generators/async-gens:** the span must stay open across the *entire* yield lifetime and close in `finally` (also fires on `GeneratorExit`/early `break`). Closing at first yield gives zero/wrong latency — explicit pitfall.
- `functools.wraps` to preserve metadata; default `name = func.__qualname__`.

### 4.4 `span()` — context manager + manual handle (one core)

```python
with span("search", type="tool_call", input=query) as s:
    result = do_search(query)
    s.set_output(result)
    s.set_usage(input_tokens=..., output_tokens=...)   # optional
```

- One class implements sync (`__enter__`/`__exit__`) **and** async (`__aenter__`/`__aexit__`), returns `self` so callers attach output/usage/attributes mid-block.
- `__exit__` inspects `exc_info`: on exception, record error + `status=error`, set end time, enqueue, and **return False** (do not suppress).
- **Manual API** shares the same primitives: `s = agentlens.start_span(name, type=...)` → `s.end(output=..., error=...)` / `s.record_exception(e)`. All three entry styles (`@trace`, `with span`, manual) produce identical rows.

### 4.5 Context propagation — RATIFY `context.py`, harden `reset`

The scaffolded `context.py` is correct in shape (module-level `ContextVar`, `push/pop`). Two hardening amendments from research:

1. **Guard `pop_span` against the cross-context `reset` trap.** `ContextVar.reset(token)` raises `ValueError: Token was created in a different Context` when set and reset happen on opposite sides of an async/thread boundary (or in concurrent `asyncio.gather`). Wrap:
   ```python
   def _exit(token, parent):
       try:
           _current_span.reset(token)
       except ValueError:
           _current_span.set(parent)   # restore parent instead of crashing
   ```
   Keep `set` and `reset` within the **same** wrapper scope so this is rare, but never let it raise.
2. **Threads do not propagate contextvars.** A new `threading.Thread` / `ThreadPoolExecutor` worker starts with empty contextvars → child spans detach (`parent_id=None`), producing flat trees. **Ship `agentlens.TracedThreadPoolExecutor`** (subclass overriding `submit` to wrap the fn in `contextvars.copy_context().run`) and **document** that raw threads and `loop.run_in_executor` need `copy_context().run(...)`. `asyncio` propagates automatically because `asyncio.Task` copies context at **task-creation** time — document that `create_task` must be called *inside* the active span.

### 4.6 Safety + serialization — RATIFY `serialization.py`, add redaction

The scaffolded `serialization.py` (`to_jsonable` with pydantic v1/v2, dataclasses, bytes, depth/item caps, `repr` fallback, truncation) is **excellent and matches research** — ratify. Three additions:

1. **Redaction:** before serializing a dict, drop/replace values for keys in `redact_keys` (case-insensitive) with `"[redacted]"`. Strips `api_key`/`authorization` from captured client kwargs.
2. **`capture_content` gate:** when `False`, LLM message *bodies* are replaced with a `{"omitted": true, "len": N}` marker (keep counts/roles, drop text). Default `True` for local DX; document it for users who don't want prompt text on disk.
3. **Big-payload hygiene:** collapse long base64 image data and long numeric arrays (embeddings) to `"<base64 N bytes>"` / `"<float[N]>"` markers inside `to_jsonable`. Store original byte length. (Multi-MB payloads choke SQLite and the React tree — known pain everywhere.)

**`_safe(fn, *a, **k)` helper:** a single wrapper that runs every instrumentation internal under `try/except Exception` → `logging.getLogger("agentlens").debug(..., exc_info=True)` and returns a sentinel. If *starting* a span fails, call the wrapped user callable directly. This is what makes "never crash the user's app" real.

### 4.7 Auto-instrumentation: OpenAI & Anthropic

Ship **explicit wrappers** (LangSmith `wrap_openai` style) as the primary, type-safe path, plus an optional module-level monkeypatch for the zero-friction demo.

```python
client = instrument_openai(OpenAI())        # wraps this client's methods
client = instrument_anthropic(Anthropic())
# optional magic (documented): instrument_openai() with no client patches the class.
```

- **Import `openai`/`anthropic` only inside these modules** (never at package import — would crash users without them). Behind `[openai]`/`[anthropic]` extras.
- **Idempotent:** set a sentinel attribute on the patched method; a second `instrument_*` call is a no-op (re-wrapping stacks wrappers → duplicate spans and, per the wrapt author, runaway memory). Provide `uninstrument_*` that restores the stored original (needed for tests).
- **One clean span per API call** (`type="llm_call"`), not a tree of HTTP/retry internals.

**OpenAI wrap points:** `openai.resources.chat.completions.Completions.create` + `AsyncCompletions.create` (and `responses.Responses.create`). Capture `model`, `messages`, `temperature`, `max_tokens`, `tools` into input/attributes. Non-streaming: read `resp.model`, `resp.choices[0].message`, `resp.usage.prompt_tokens/completion_tokens/total_tokens`.

**Anthropic wrap points:** `anthropic.resources.messages.Messages.create` + `AsyncMessages.create` (+ beta). Also wrap `Messages.stream` / the `MessageStreamManager` so `get_final_message()` usage is captured. Non-streaming: `resp.model`, `resp.content` (block list), `resp.usage.input_tokens/output_tokens`.

**Streaming (both):** return a transparent proxy that accumulates chunks and finalizes the span **only when the iterator is exhausted or errors** — never drain the stream yourself (that steals the user's tokens).
- Implement as a `wrapt.ObjectProxy` subclass (OpenInference pattern) when `wrapt` is importable, with a **stdlib generator-wrapper fallback** so the core stays dependency-light. Override `__iter__/__next__` (catch `StopIteration` → finalize ok; other `Exception` → record + finalize; re-raise), `__aiter__/__anext__` (catch `StopAsyncIteration`), and pass through `__enter__/__exit__/__aenter__/__aexit__` so `with client...stream() as s` still works. A finalize-once guard prevents double-close. Record only a cheap first-token timestamp on chunk 0; do the join+serialize **once** at finalize (no per-chunk JSON/DB).
- **OpenAI token capture:** usage is `null` on chunks unless `stream_options={"include_usage": True}`; the final usage-bearing chunk has empty `choices: []`. The instrumentor **injects `include_usage` when `stream=True` and the caller omitted it** (behind a flag, default on) so tokens are captured; treat the empty-choices final chunk as usage-only, not content.
- **Anthropic token capture:** `input_tokens` come from the `message_start` event; `output_tokens` in `message_delta` is **CUMULATIVE** — take the **last** value, never sum across deltas (summing double-counts — a real bug in agno/cline). Accumulate content by block index, handling `text_delta`/`input_json_delta`/`thinking_delta`.

## 6. Frontend (React + Vite + TypeScript)

**Build the waterfall by hand with plain React + one CSS file. No Gantt/charting library.** (Surveyed Gantts are PM-oriented, heavy, some licensed, and fight a span tree; the trace-specific `thundra-trace-chart` is archived.) Total bundle target ~150–200 KB gzip.

### 6.1 The waterfall mechanism (the whole trick)

Jaeger UI's approach verbatim: each row has a `position:relative` track containing one `position:absolute` bar:
```
left  = (span.start_time_ns - runStart) / runDur * 100%
width = max((span.duration_ns) / runDur * 100%, MIN%)   // clamp so tiny spans stay visible/clickable
```
- Compute `runStart = min(start_time_ns)`, `runEnd = max(end_time_ns)`, `runDur = max(runEnd - runStart, 1)` **once** per run (`useMemo`). **Guard `runDur === 0`** before dividing (single instantaneous span → NaN).
- **Indentation expresses hierarchy (left gutter only); horizontal position expresses time.** Never position bars by depth — the canonical homemade-waterfall bug.
- **Unit discipline:** the API sends `*_ns`; divide in ns consistently. (Mixing units silently makes bars 1000× off.)

### 6.2 Tree → flat visible list

API returns a nested tree. Keep collapse state as `useState<Set<string>>` of collapsed span IDs. A memoized `flatten(tree, collapsed) → {span, depth}[]` pre-order walk skips collapsed subtrees. Render the flat array as uniform rows (faster than recursive component nesting; ~120ms vs ~180ms @800 nodes). `depth` drives only `paddingLeft = depth*16 + caret`. Caret (▸/▾) only on rows with children. Expand-all / collapse-all buttons. Collapsed parents still show their own (rolled-up) bar.

### 6.3 Component breakdown

```
src/
  main.tsx
  App.tsx                  // view switch: list <-> selected run (useState; NO react-router for v1)
  api.ts                   // useFetch<T>(url) hook: fetch + {data,loading,error}; typed
  types.ts                 // RunSummary, Run, SpanNode — 1:1 port of pydantic models
  theme.css                // CSS custom properties; dark default
  components/
    RunList.tsx            // page 1: table of RunSummary (name, status badge, started, duration, spans, errors, tokens, models)
    RunView.tsx            // page 2: layout = TimeAxis + Waterfall + SpanDetailPanel
    TimeAxis.tsx           // tick ruler (0 / 25 / 50 / 75% / total) using the same pct() fn
    Waterfall.tsx          // maps flattened rows -> SpanRow
    SpanRow.tsx            // gutter (caret+type dot+name, indented) | track (absolute bar); click selects
    SpanDetailPanel.tsx    // right drawer: header(name+type badge+status), timing, Input, Output, Tokens, Attributes, Error(red, shown first when present)
    JsonView.tsx           // wraps @uiw/react-json-view (lazy import) OR <pre>{JSON.stringify(v,null,2)}</pre>
    StatusBadge.tsx, TypeDot.tsx
```

- **Selection → right-side `SpanDetailPanel`** (dominant pattern, keeps waterfall visible for context). Sections: Input, Output, Tokens (input/output/total), Attributes, **Error styled red and shown first/expanded when present**. "See more/less" truncation for large payloads.
- **Color-coding** via CSS vars, one accent per type (`--span-llm` indigo, `--span-tool` teal, `--span-agent` amber, `--span-chain`, `--span-retrieval`); **error overrides type color → red bar + red dot/⚠ badge** so failures are scannable. Error must **not** be color-only (a11y) — pair with icon/text. Test WCAG-AA contrast of white text on mid-saturation bars over the dark bg.
- **Dark mode:** CSS custom properties on `:root` (dark default); optional `[data-theme="light"]` override toggled on `<html>`. No Tailwind (overkill for one view).
- **Data fetching:** plain `fetch` in a ~20-line `useFetch<T>` hook. **No React Query/SWR/axios/Redux** for a local read-only 2-endpoint app.
- **Dependencies:** `react`, `react-dom`, `vite`, `typescript`, `@types/*`, and optionally **`@uiw/react-json-view`** (~20KB, zero deps, dark theme) for pretty payloads. **Avoid** legacy `react-json-view` (~50KB, unmaintained) and Monaco (~2MB). `<pre>+JSON.stringify` is an acceptable zero-dep fallback for v1.
- Virtualization (react-virtualized) is a **noted future optimization** for runs with hundreds+ of spans — do **not** add it now.

## 8. Testing strategy

`pytest` + `pytest-asyncio` (already in `[dev]`). Use `:memory:` SQLite (already supported) for unit tests; a `tmp_path` file DB for writer/flush and API tests.

**Model/storage**
- `seq` increments per run; `ORDER BY start_time_ns, seq` yields correct chronological order for siblings sharing a timestamp.
- `duration_ms` derived correctly from ns; `end_time_ns >= start_time_ns` even under a simulated clock shift (monotonic perf clock).
- `to_jsonable`: pydantic v1/v2, dataclasses, `datetime`, `set`, bytes, a deliberately non-serializable object (raises in `__repr__`), deep/recursive structure, oversized payload (truncation marker present, size capped), redaction of `api_key`/`authorization`, base64/embedding collapse.
- Round-trip: save_run/save_span → get_run/get_spans returns equal data; `list_runs` rollups (span_count, error_count, total_tokens) correct.

**Tracer / context (the highest-value tests — misleading trees are worse than no tracing)**
- A **parent-id correctness matrix**: (a) flat, (b) nested sync, (c) `@trace` + nested `with span`, (d) `asyncio.gather` siblings attach to the right parent, (e) raw `threading.Thread` detaches (documents the limitation), (f) `TracedThreadPoolExecutor` re-attaches correctly, (g) concurrent `asyncio` tasks don't cross-link.
- `@trace` over all four shapes (sync, coroutine, sync-gen, async-gen) — span spans the **whole** generator lifetime, closes on early `break`/`GeneratorExit`.
- Exception path: span `status=error`, `ErrorInfo.type`==class name, traceback captured, **exception re-raised** unchanged.
- **Fail-silent:** monkeypatch the writer's enqueue to raise → user function still returns its value (tracing degrades, app survives).
- `pop_span` cross-context guard: force a `reset` in a different context → no `ValueError` escapes.

**Auto-instrumentation (no network — use fakes/`unittest.mock`)**
- Fake OpenAI/Anthropic clients returning canned response objects: one `llm_call` span per call with correct `model`, normalized `usage` (prompt/completion → input/output), input/output captured.
- **Streaming:** fake chunk iterators. OpenAI: assert content assembled and usage read from the empty-`choices` final chunk; `include_usage` injected when omitted. Anthropic: assert `output_tokens` taken from the **last** `message_delta` (not summed) and `input_tokens` from `message_start`. Assert the proxy **does not pre-drain** (user receives every chunk).
- **Idempotency:** double `instrument_openai()` → exactly one span per call; `uninstrument_*` restores the original.

**Background writer**
- Enqueue N spans, `flush()`, assert all N persisted; `seq` assigned in-writer without an N+1 `SELECT COUNT`.
- `atexit`/`flush` ordering: `demo` writes then serve reads sees the data.

**API (FastAPI `TestClient`, `[dev]` has httpx)**
- `/api/runs` shape + rollups + ordering; `/api/runs/{id}` returns a correctly nested tree with raw (unparsed) heavy fields; `/api/runs/{id}/spans/{id}` returns parsed detail; 404s for missing ids; `/api/*` not shadowed by the static mount.

**Frontend (light for v1)**
- Vitest unit test for `flatten(tree, collapsed)` (skips collapsed subtrees, correct depth) and the `pct()`/`runDur===0` guard. A smoke render of `Waterfall` with a fixture. Keep it minimal — the Python side carries the test weight.

**Tooling:** `ruff` + `mypy` (config already present). CI matrix Python 3.9–3.12. A packaging smoke test: build the wheel, assert `_webui` is inside it, `pip install` it in a clean venv, run `agentlens demo --serve --no-browser` headless and curl `/api/health`.

## 9. Risks & open questions

1. **Naming/rename cost.** Must rename before publish (`agentlens` is taken). Decide dist name (`lenstrace` recommended) and whether to also rename the import package. *Blocking for publish, not for building.* — **Owner decision needed now.**
2. **Background writer vs. simplicity.** Adds a thread + queue + `atexit`. Mitigated by keeping it small and fail-silent; tests cover flush ordering. The alternative (sync writes) is the known Langfuse latency trap — accept the complexity.
3. **`wrapt` optional vs. required.** Streaming proxies are cleanest with `wrapt.ObjectProxy`. v1 ships a stdlib fallback to honor "stdlib-only core," but the fallback proxy is more code to maintain. *Open: is `wrapt` acceptable as a soft dep advertised in `[openai]`/`[anthropic]` extras?* Recommendation: yes — list `wrapt` in those extras, keep the stdlib fallback for the pure-core path.
4. **`capture_content` default.** Defaulting to capturing prompt bodies is great DX but stores text (and possibly PII) in a local file. Mitigated by redaction + it being local-only + a documented off switch. Confirm this is acceptable for the target audience (it is, for a local dev tool).
5. **In-flight spans not streamed to DB.** A process that crashes mid-run leaves `running` spans (or none, if not yet flushed). v1 accepts this; a future enhancement can write a lightweight "started" row. *Open, low priority.*
6. **OTel exporter scope.** This brief bakes in the *seams* (hex ids, status map, ns times, dotted attribute keys, type→kind map) but `agentlens export --otlp` is **explicitly out of v1 scope.** Re-confirm it stays out.
7. **FastAPI `app.frontend` version skew.** Native SPA support is recent (0.138+). v1 feature-detects and falls back to a `SPAStaticFiles` subclass so it works on widely-installed FastAPI. Verify the fallback handles deep-link refresh.
8. **Repo doc drift.** README/REQUIREMENTS reference `ARCHITECTURE.md`/`DATA_MODEL.md`/`WORKFLOW.md`/`ROADMAP.md` that don't exist, and the old name "AgentTrace" lingers. Create or delete the dangling links and scrub the placeholder name before publish.

## Top decisions (structured)

1. **Rename the PyPI distribution (recommend 'lenstrace') and keep 'AgentLens' only as the brand and the CLI command name; do NOT publish as 'agentlens'.**

   _Why:_ 'agentlens' is already an active PyPI package (v0.1.44, an agent-scaffold lib) and PyPI normalizes agentlens/agent-lens/agent_lens to one name, so `twine upload` of the current pyproject (name='agentlens') will be rejected. 'lenstrace' and 'agentscope-lens' are verified free; 'spanlens'/'tracelens' are taken (spanlens is a direct competitor). The console command stays 'agentlens' since the binary name is independent of the dist name.

2. **Store timestamps as integer nanoseconds (start_time_ns/end_time_ns via time.time_ns for wall clock + time.perf_counter_ns for monotonic duration), persist a derived duration_ms REAL, and keep the existing per-run 'seq' tiebreaker. Amends the scaffolded float-epoch-seconds model.**

   _Why:_ Nested agent spans are frequently sub-millisecond; float-second math loses ordering/precision (the OTel rationale for ns). Using a monotonic perf clock for duration keeps end>=start across clock shifts/retries; ORDER BY (start_time_ns, seq) gives correct chronological+sibling order with one index and no recursive CTE, making the LangSmith single-string ordering key unnecessary.

3. **Introduce a background SpanWriter thread (queue + batched transactions, in-writer per-run seq, flush()+atexit, fail-silent) and write each span once on completion. Replaces the scaffolded synchronous, per-call locked writes (which also did an O(n) SELECT COUNT per span for seq).**

   _Why:_ Synchronous on-hot-path writes + per-event work are exactly Langfuse's documented '50s -> 10ms' latency disaster; the principle is keep the caller's path to capture+enqueue+return. Computing seq from an in-memory counter removes a hidden O(n^2) read. Batching converts many tiny commits into few; WAL lets the dashboard read concurrently from a separate read-only connection.

4. **Make parent/child purely implicit via the existing contextvars (no manual parent IDs ever), but harden it: guard ContextVar.reset against the cross-context ValueError (fall back to set(parent)), and ship a TracedThreadPoolExecutor plus docs for copy_context().run since threads don't propagate context.**

   _Why:_ Implicit nesting is the difference between 'frictionless' and 'annoying' and is what every leading tool does. reset(token) raises 'Token was created in a different Context' across async/thread boundaries and in asyncio.gather (multiple confirmed real-world bugs); raw threads/run_in_executor start with empty contextvars and silently produce flat trees. Both must be handled or nesting breaks misleadingly.

5. **Wrap every tracing internal in fail-silent try/except (a _safe helper) and reuse the scaffolded defensive serializer, adding key-based redaction (api_key/authorization), a capture_content gate, size caps, and base64/embedding collapse. Tracing must never raise into user code.**

   _Why:_ Serialization of arbitrary agent inputs WILL hit non-serializable objects, recursion, secrets, and multi-MB payloads; if any tracing side effect can raise, it breaks the very app being observed, and huge payloads bloat SQLite and choke the React tree. Fail-silent + truncate + redact is the universal hard-won lesson across the surveyed tools.

6. **Ship explicit instrument_openai(client)/instrument_anthropic(client) wrappers that emit ONE clean llm_call span per call, are idempotent (sentinel + uninstrument), normalize tokens to input/output/total, and handle streaming via a transparent proxy that finalizes only on iterator exhaustion.**

   _Why:_ Auto-instrumentation of the raw SDKs is the highest-impact 'wow' feature; explicit wrappers (LangSmith style) are the most type-safe and least magical. Re-wrapping stacks duplicate spans and per the wrapt author causes runaway memory, so idempotency is mandatory. Streaming has sharp edges: OpenAI needs stream_options include_usage and its final usage chunk has empty choices; Anthropic's message_delta output_tokens are CUMULATIVE (must take last, not sum) with input_tokens from message_start; and you must never pre-drain the user's stream.

7. **Build the dashboard as plain React+Vite+TS with a hand-rolled CSS waterfall (Jaeger-style absolute bar: left/width as % of run duration; indentation = hierarchy only), a tree->flat-visible-list render with a collapsed Set, a right-side detail panel, dark-default CSS variables, plain fetch (no React Query/Gantt lib), optionally @uiw/react-json-view. Keep heavy span I/O as raw strings in list/tree endpoints and parse only on single-span detail.**

   _Why:_ The collapsible waterfall is one CSS trick, not a charting problem; Gantt/charting libs are heavy, some licensed, and fight a span tree. Positioning bars by depth instead of time is the classic homemade bug, so hierarchy (gutter) and time (bar) must be separated, with a runDur===0 guard. Avoiding eager json.loads on list/tree endpoints is the exact Langfuse v1->v2 performance fix. This keeps the bundle ~150-200KB and the codebase tiny while delivering the proven primary view.

8. **Add an OTel/OpenInference compatibility seam at zero runtime cost: switch ids to secrets.token_hex (32-hex run/16-hex span), keep OTel-aligned token names, add an attributes JSON column (separate from user metadata) keyed by canonical dotted names (gen_ai.*), and document a type->openinference.kind/gen_ai.operation.name map. Keep status as running/ok/error (deliberate, documented divergence from OTel UNSET). Defer the actual OTLP exporter out of v1.**

   _Why:_ Mirroring OTel ids/status/ns-times/dotted attribute keys/type-map makes a future `agentlens export --otlp` buildable from existing rows with no re-modeling and makes the data instantly familiar, all without importing opentelemetry into the stdlib-only core. 'running' carries more info than UNSET for a local dashboard that may render in-progress runs and AgentLens always resolves to ok/error on end, so UNSET would never persist. Using one JSON attributes column (Phoenix/Langfuse pattern) beats an EAV table for local-scale read performance.

9. **Move fastapi/uvicorn into a [server] optional extra (core dependencies = none/stdlib-only), import them lazily via PEP 562 __getattr__, vendor the built React app inside the package at src/agentlens/_webui and serve it via importlib.resources.files (never __file__), mounting the SPA at '/' AFTER /api routes; change the default dashboard port from 4317 to 8765.**

   _Why:_ Making fastapi/uvicorn core forces server deps on SDK-only users and slows import agentlens; lazy + extras keeps the core light while serve prints an actionable 'pip install agentlens[server]'. importlib.resources survives zipped wheels where __file__ breaks; mounting static before the API shadows the API. 4317 is the canonical OTLP gRPC port (Phoenix/collectors), so reusing it for an HTTP UI causes address-in-use/wrong-protocol confusion for exactly this audience; 8765 avoids the collision.

10. **Resolve the SQLite path through one shared chain for SDK and dashboard (explicit > $AGENTLENS_DB > ./agentlens.db if writable > ~/.agentlens/agentlens.db) and print the resolved absolute path on first write and on serve startup; lead with a no-API-key `agentlens demo` that writes a nested run including a deliberate error.**

   _Why:_ The #1 'it says no runs' footgun is the SDK writing ./agentlens.db while serve reads ~/.agentlens; a single resolver plus a printed path eliminates it. A zero-key demo that produces a real nested-with-error trace proves the whole capture->store->serve loop instantly and showcases the local-first wedge (pip install, one file, no accounts/Docker) that is AgentLens's clearest advantage over Phoenix/Langfuse self-hosting.
